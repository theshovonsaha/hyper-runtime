# Runtime Lab Showcase

Status: implemented

## Objective

Expose a public-facing comparison laboratory that runs specialized agents on
the same objective, evaluates their canonical events, and makes both strengths
and confounds visually obvious.

## Integrity rules

- Live variants cannot disable policy, observation, or verification.
- Unsafe ablations remain deterministic fixture evidence.
- Declared modules and modules actually exercised are separate fields.
- A successful tool return is not a successful task.
- Rankings are withheld when objectives differ materially.
- Provider, model, and authority-profile differences are displayed as
  confounds rather than silently attributed to an agent design.
- Scores summarize observed mechanisms; they do not establish general
  intelligence or arbitrary factual truth.

## Delivery path

1. Register three bounded lab-agent configurations.
2. Record experiment, agent, and module identity in each canonical run ledger.
3. Analyze policy, effect, observation, verification, recovery, routing,
   context, evidence, retry, and timing events.
4. Compare two to four archived runs or launch two to three fresh runs.
5. Present score matrix, automatic findings, module exercise audit, canonical
   event drill-down, and separately labelled deterministic benchmarks.

## Acceptance gates

- False-success, unresolved-effect, retry-pressure, verified-completion, and
  comparison-confound detectors have deterministic tests.
- Lab endpoints never return provider credentials or hidden reasoning.
- Fresh comparisons use isolated sessions and ordinary runtime endpoints.
- The frontend production build and full repository check pass.
